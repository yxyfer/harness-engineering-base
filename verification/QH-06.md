# QH-06: Profiles and prerequisite diagnosis

Date: 2026-10-01. Scope: Step 06 only; no installer or Step 07 implementation.

## Outcome

Shared read-only resolution now drives check, policies, inspect and doctor.
Reviewed requirements are retained; contradictory detection blocks execution.
Tools do not influence applicability. Doctor diagnoses context and prerequisite
presence without installing dependencies, rewriting configuration or executing
quality controls. Existing project-owned config remains unchanged.

mode. Schema 2 is a reviewable example side file, not automatic replacement.

and capability mapping are documented in docs/QUALITY.md and ADR-008.

## Boundaries and limitations

- Next.js applicability is implemented; framework-specific and browser controls
  explicitly fail unsupported. The historically named Next.js fixture has no
  Next dependency and remains a synthetic JS/TypeScript fixture, not Next QA.
- All currently requested application capabilities return unsupported rather
  than imaginary assurance. Security off means no scanner assurance; v2 local
  and ci fail unsupported. No browser/security foundation is shipped.
- Multi-package aggregation is unsupported. Run individual package roots;
  workspaces and nested manifests cannot silently claim aggregate coverage.
- Doctor checks prerequisite presence, not tool usability, prose adequacy or
  passing tests. Exit 0 means ready to run controls, not verified.
- Existing optional native-check degradation remains until Step 07. Mandatory
  CI native phases were actually run; doctor missing prerequisites fails.
- Advisory source/function size prompts remain visible. Resolver and doctor
  functions retain cohesive fixed mappings, without introducing a policy DSL;
  the regression file groups one contract. No threshold was weakened.
- Release inventory explicitly adds six intended shipped inputs (72 total).
  Only this authoring release's reviewed checksums were regenerated. Consumer
  conflicts remain failures; no installed consumer manifest was repaired away.
- Existing Step 05 changes are preserved. No remote publication or protection
  change occurred; remote execution remains unverified.
