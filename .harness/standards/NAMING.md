# Naming

Use names that explain the domain concept or action. Avoid vague names such as
`manager`, `helper` or `data` when a more specific name is available.

Follow framework file conventions and existing local naming. Use PascalCase for
React components and TypeScript types, camelCase for values and functions, and
descriptive kebab-case filenames outside framework conventions. Name tests after
observable behaviour. Do not rename unrelated code for consistency alone.
