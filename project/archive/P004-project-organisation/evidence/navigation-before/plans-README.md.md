## Keep work readable

1. A plan states outcome, sequence, dependencies and next action.
2. A task states acceptance, implementation choice, risk and recovery.
3. Architecture and ADRs explain the durable system; reports record evidence.

Link between these records. Update state in place. Do not paste task details,
commands/results or chronological progress notes into the plan. Historical
reports retain their original scope; later evidence is linked explicitly.
Never mark human acceptance complete from an automated pass.

Create bounded work from the [plan](../../../../templates/plan.md) and
[task](../../../../templates/task.md) templates. Close by moving the plan,
updating
incoming links and indexes, and retaining its final evidence.
