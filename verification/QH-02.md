## Implementation and compatibility

`test` resolves CLI > environment > config > package script > Python convention.
It never implicitly selects shipped harness tests. `[tool.harness.tests]` in
`pyproject.toml` declares `runner = "pytest"` or `"unittest"`; undeclared Python
testing defaults to pytest, independently of module availability. Missing pytest
fails with selected-interpreter/setup guidance. An invalid declaration fails
without a traceback. Native pytest configuration still controls its scope.

Automatic Python tests prefer the target `.venv/bin/python`; incomplete local
environments fail. Valid local environments are also put on PATH for native
test overrides. Explicit executable paths/commands stay authoritative. Metadata
uses a TOML-capable host interpreter; the unittest execution path does not
require importing TOML in the application's interpreter. Only Python 3.14 was
exercised; no new Python-version/platform guarantee is inferred.

`self-test [target]` runs the executing kit's suite with the kit-root Python
environment. It ignores the target's package script, runner and test overrides;
`--command` is rejected. Co-located kit/app roots share their local environment.
No self-test config key or config schema change was introduced. The existing
public exits remain stable, including underlying native exits in diagnostics.

The root's explicit test command directly invokes guarded stdlib discovery and
never calls `harness test`/`self-test` recursively. Separate managed
`default-config.toml` keeps that repository-only command out of external targets.
Full app installation regressions use the automatic default, not this
repository's deliberately overridden suite command. Consumers cloning this
repository must replace that root command with their app command or leave it
empty; project configuration remains owner-controlled.

The Python HTTP fixture now explicitly declares unittest, replacing its unused
pytest declaration. Its behaviour/tests are unchanged. Node fixture source,
scripts, dependencies and lockfile are unchanged. Arbitrary command overrides
and Node scripts retain responsibility for their own collection contract;
complete cross-runner required-case/skip/artifact enforcement is Step 08.

The adapter uses stdlib `countTestCases()` to reject empty unittest discovery
before execution. Real pytest zero-collection returns exit 5, as verified here
and documented in [pytest's exit contract](https://docs.pytest.org/en/stable/reference/exit-codes.html).
No fake pytest implementation substitutes for collection evidence.
